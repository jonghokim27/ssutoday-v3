# 스터디룸 페널티

## 정책

| 종류 | 부여 시점 | 효과 |
| --- | --- | --- |
| 인증샷 미촬영·미인정 (`PHOTO`) | 기한 내 미촬영으로 자동 취소, 자동 검사 2회 미인정으로 취소, 관리자가 이용 종료 후 7일 안에 스터디룸 외부 촬영으로 판정 | 1회 부여, 부여 시각부터 30일간 유효 |
| 부정 예약 (`FRAUD`) | 관리자가 매크로·타인 계정·인증샷 재사용으로 판정 | 부여 시각부터 90일간 예약 정지, 해당 예약 즉시 취소 |

유효한 인증샷 페널티 횟수에 따라 하루 최대 예약 시간이 줄어든다. 관리자는 제한을 받지 않는다.

| 유효 횟수 | 하루 최대 예약 |
| --- | --- |
| 0~1회 | 3시간 |
| 2회 | 2시간 |
| 3~4회 | 1시간 |
| 5회 이상 | 4회로 줄어드는 만료 시각까지 예약 정지 |

예약 정지 중에는 `/reserve/request`가 `SSU4094`로 저장 전에 거부한다. 요청을 받은 뒤 정지된 경우에는 consumer가 예약 요청 상태 `8`(`SUSPENDED`)로 거부한다. 이미 잡혀 있는 예약은 줄어든 시간 때문에 취소하지 않는다.

같은 예약에는 종류별로 한 번만 부여한다. 관리자가 버튼을 연달아 눌러도 예약 행 잠금과 DB 유니크 키(`reservation_id`, `active_type`)로 한 건만 저장된다. 취소한 페널티는 지우지 않고 `revoked_at`을 남긴다. 기준은 `PenaltyPolicy`에 있으며 앱의 단계 표시는 `frontend/src/features/reservation/data/penalty.ts`가 같은 값을 쓴다.

## 대상

`PENALTY_TARGET_MAJORS`(기본값 `cse`, 컴퓨터학부)에 속한 학생만 페널티 대상이다. 대상이 아닌 학생은 인증샷을 촬영하지 않아 예약이 취소돼도 페널티가 붙지 않고, 관리자 화면에서도 인증샷 미인정과 부정 예약을 모두 부여할 수 없다. 예약 홈의 페널티 버튼도 대상 학생에게만 보인다. 여러 학과를 지정할 때는 `cse,media`처럼 쉼표로 구분한다.

## 시행일

인증샷 페널티는 `PENALTY_PHOTO_START_DATE`(기본값 `2026-11-01`) 이후 이용한 예약에만 부여한다. 그 전 예약은 자동 취소돼도 페널티 없이 기존 취소 알림만 보낸다. 부정 예약은 시행일 없이 바로 적용한다.

## 배포

서버 배포 전에 [DDL](../infra/sql/20261025-penalty.sql)을 적용한다. 알림을 눌러 페널티 현황 화면으로 이동하는 것은 `path`를 지원하는 모바일 앱부터 동작한다. 이전 버전 앱은 예약 내역으로 이동한다.

## 관리자 처리

관리자 작업은 기존 예약 취소·인증샷 삭제와 같이 Discord 버튼으로 여는 `/admin/action` 페이지에서 한다. `ADMIN_BASE_URL`이 없으면 버튼이 붙지 않는다.

- **부여:** `[인증샷 촬영 알림]`의 `페널티 부여` 버튼을 누른다. 화면에서 현재 상태와 부여 후 상태를 확인하고 종류, 사유, 처리자를 입력한다. 부정 예약은 이용 전인 다른 예약을 함께 취소할지 고를 수 있으며 기본으로 선택돼 있다.
- **취소:** 자동·수동 부여 모두 `[페널티 부여 알림]`이 남는다. 이의제기를 받으면 이 알림의 `페널티 취소` 버튼으로 취소 사유와 처리자를 입력한다. 취소 사유는 학생에게 보내지 않는다.

인증샷 알림이 없는 예약에 부정 예약을 부여할 때는 예약의 관리자 토큰으로 직접 페이지를 연다.

```sql
SELECT id, student_id, date, start_block, end_block, admin_token FROM reservation
WHERE student_id = :student_id ORDER BY date DESC, start_block DESC LIMIT 10;
```

`{ADMIN_BASE_URL}/admin/action?token={admin_token을 URL 인코딩한 값}&action=penaltyGrant`

## 학생 알림

모든 페널티 알림은 `reservation` 종류에 `path=/reservations/penalties`를 실어 보낸다. `path`를 아는 앱은 누르면 페널티 현황 화면으로, 이전 버전 앱은 예약 내역으로 이동한다.

| 상황 | 제목 | 본문 |
| --- | --- | --- |
| 미촬영 자동 취소 | ❌ {시설} 예약이 취소되었어요 | 인증샷을 촬영하지 않아 예약이 취소되고 페널티 1회가 부여되었어요 |
| 2회 미인정 취소 | ❌ {시설} 예약이 취소되었어요 | 인증샷이 2회 인정되지 않아 예약이 취소되고 페널티 1회가 부여되었어요 |
| 관리자 사후 부여 | ⚠️ 페널티 1회가 부여되었어요 | {이용일} {시설} 이용 건의 인증샷이 스터디룸 외부에서 촬영된 것으로 확인되었어요 |
| 부정 예약 | ⛔ 스터디룸 예약이 정지되었어요 | 부정 예약이 확인되어 해당 예약이 취소되었어요. {해제일}까지 신규 예약이 제한돼요. (사유: …) |
| 페널티 취소 | ✅ 페널티 1회가 취소되었어요 | {부여일}에 부여된 페널티가 취소되었어요 |
| 정지 해제 | 🔓 예약 정지가 해제되었어요 | {부여일}에 부여된 부정 예약 페널티가 취소되어 지금부터 예약할 수 있어요 |

자동 취소에 페널티가 붙으면 취소 알림 한 건에 함께 안내해 알림이 두 번 가지 않게 한다.

## 조회

```sql
-- 학생별 유효 페널티
SELECT student_id, type, COUNT(*) FROM penalty
WHERE revoked_at IS NULL AND expires_at > NOW()
GROUP BY student_id, type ORDER BY COUNT(*) DESC;
```
